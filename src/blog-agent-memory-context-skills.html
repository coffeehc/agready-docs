PRACTICAL GUIDE · NOVEMBER 11, 2026

AI agent memory vs context vs skills: what to save between tasks

Use context for the task in front of you, memory for information that remains useful across sessions, and skills for repeatable methods. Keeping those roles distinct makes it easier to resume work and correct stale assumptions.

Anthropic's November 6, 2026 article, The components of agent memory, distinguishes retained knowledge between sessions from model training and context compaction. It is a useful distinction for anyone building a continuing agent workflow, including a self-hosted workspace.

What belongs in each layer?

Context: what the model can use for this response

Context can contain instructions, the relevant conversation, selected memories, loaded skill instructions and tool results. The context window has a limit. A long conversation may use summaries or selected history rather than include every earlier message in every request.

Memory: what should remain useful later

Memory holds durable information that can be retrieved for another session. Examples include an accepted project decision or a stable reporting preference. A stored record still needs to be relevant, current and available to the task that uses it.

Skills: how to perform a recurring type of work

A skill describes a method, with supporting material where needed. A comparison skill might require source references, like-for-like fields and explicit unknowns. The Agent Skills specification packages those instructions separately from the changing input for each task.

These categories overlap at execution time: selected memory and skill instructions can become part of the active context. The useful distinction is their purpose and lifetime, not a promise that they occupy three isolated boxes.

A worked example: a continuing research project

Imagine a fictional team preparing a monthly documentation review. It has five pieces of information. Here is how to organize them:

  • “Use concise English summaries for the monthly review.” A stable preference, if the user wants it to continue, belongs in memory with the project scope.
  • “Compare coverage, setup effort and update frequency, and cite each finding.” A reusable review method belongs in a skill.
  • “This month, review products Cedar, Harbor and Maple.” Current task input belongs in the task brief.
  • “The Cedar source was checked; Harbor and Maple remain unread.” Current progress belongs in a work record or handover, with source references and dates.
  • “A password for the source system.” This belongs in the supported credential mechanism, never in a skill, memory note or reusable prompt.

Saving every temporary status as a durable memory creates stale information to reconcile later. Keeping only a vague “research in progress” summary loses the evidence needed to resume. Preserve the changing work state separately and link back to the actual source packet.

A short handover for the next session

This example is a reusable brief for a fictional workflow, not an executed AgReady result. Fill it with references the next session can actually access.

Goal: prepare the monthly documentation comparison.

Stable preference: concise English summary for this project.
Method: compare coverage, setup effort and update frequency.
Cite the source for each factual comparison; mark unknowns explicitly.

Current inputs: Cedar, Harbor and Maple source packet, version 3.
Verified progress: Cedar's setup page was read on November 11, 2026.
Pending: read Harbor and Maple; check source dates; draft the comparison.
Uncertain: whether the earlier export created a file. Check before retrying.

Current exception: this month's draft must use bullets, not a table.
Allowed now: inspect the supplied sources and return a draft here.
Do not send, publish, change saved preferences or contact other agents.

Before continuing, summarize what is accessible and what is missing.

A useful continuation preserves the pending items and the uncertain export. It follows the current bullet-format exception without treating it as a permanent preference. If the source packet is unavailable, it asks for that input rather than filling the gaps from memory.

Diagnose the failure before adding more memory

  • The agent used an old deadline. Check the current source and whether the task clearly superseded the earlier date. Correct the relevant record instead of creating another contradictory note.
  • The agent forgot a reporting preference. Check whether it was saved, whether the project scope matches and whether it was selected for this task.
  • The agent repeated a completed action. Improve the execution record and outcome checks. A formatting preference cannot resolve an uncertain external action.
  • The agent follows a method inconsistently. Inspect the skill's instructions and test them on a small input. More biographical memory is unlikely to clarify an ambiguous method.
  • The agent missed a source. Check retrieval and document coverage. A larger context window cannot make an unread document appear in the task.

For a memory check, first inspect the saved entry. Then use a fresh, harmless task that needs the preference without repeating its exact answer in the prompt. A correct response is useful evidence, but by itself it does not establish which retrieval path supplied the information.

How AgReady separates these concerns

AgReady has session context and compression, cross-session memory, and reusable Skills. Its current development design keeps session continuity summaries separate from long-term memory. Long-term records can hold stable preferences, accepted decisions and facts; temporary task progress belongs with the session's work state.

This description is based on development source checked November 11, 2026. It describes existing capability and design, not a guarantee that every useful fact is retained or that every release exposes identical controls.

Use sessions and context to resume work, the memory guide to inspect and correct saved information, and the Skills guide to package a method. Start with one small project and keep its current brief authoritative.

If the task also needs new tools or a remote specialist, see Agent Skills vs MCP vs A2A. A connection adds access; it does not decide which information should become a lasting memory.
