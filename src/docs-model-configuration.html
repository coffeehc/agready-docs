Configure and test a model connection

Configure a model connection, test it, and verify a small task before making it your default. Saving the form alone does not demonstrate that the provider accepted a request.

These controls describe the October 2026 development interface; labels and availability may differ in your installed release.

Prepare the connection details

Get the API protocol, upstream model identifier, Base URL and credentials from your provider or instance administrator. Use a model and account you are authorized to access. Model requests can leave your machine; consider the provider's data policy before supplying private content.

During initial setup, use Configure model. For subsequent management, open System config → Model config where that interface is available.

Fill the fields deliberately

Provider type

The protocol actually supported by the endpoint

A provider's brand name alone does not establish its API protocol.

Model name

A stable, recognizable name for this connection in AgReady

It is not necessarily the provider's model ID.

Upstream model

The exact identifier accepted by the provider

A marketing model name may not be a valid API identifier.

Base URL

The endpoint supplied for that protocol

Do not copy a URL from a different provider or the illustrated setup guide.

API Key

The credential for that endpoint, entered only in your instance

Never include it in an example, screenshot or support request.

Context tokens and capability settings

Values supported by the model and connection

A larger configured value does not increase the provider's actual limit or add capabilities.

https://api.example.com/v1 and example-chat-model in the illustrated walkthrough are fictional placeholders, not working configuration values. This guide does not claim universal provider compatibility.

Test, save and verify

  1. Use Test connection on your own configuration.
  2. Expand Latest test result and read the actual status. Do not infer success from the form closing or a saved notification.
  3. If the test passes, use Save model and confirm the intended configuration appears in the model list.
  4. Open Main Agent, check the selected model, and run the small first task.
  5. Check the response against the supplied notes. Only then choose the model as your default for routine work.

A connection test verifies less than a complete task. A text response does not establish that image input or tool use works. Verify additional capabilities separately with appropriate, non-sensitive inputs.

Run a small model verification task

After saving, use the intended model in a fresh session with no confidential context or attachments. This fictional example needs no browsing, files or external tools; it separates a basic response check from integration setup. It is a suggested check, not a reported AgReady test result.

Use only these fictional notes: Alex owns the draft due Friday. Morgan owns the review; no deadline is stated. Return two bullet points, each with owner, task and deadline. Write “not stated” for missing information. Do not browse, call tools, create files or send anything.

What to check: the response should contain Alex / draft / Friday and Morgan / review / not stated. It should not invent a date or claim to have saved or sent a file. Check the visible run as well as the answer. If no response arrives, read the actual error before changing settings.

This checks one small text task only. It is not a benchmark, a guarantee of reliable answers, or proof of tool calling, image understanding or long-context support. For file work, try a non-sensitive sample using the files and workspace guide. For an external action, check tool readiness and permissions separately and define its allowed scope before running it.

Troubleshoot a model connection that does not work

Start with the failing step: connection test, saved-model selection, text response or tool action. The checks below are diagnostic suggestions, not a list of guaranteed provider error messages.

The connection test fails

Read Latest test result. Compare the selected protocol, Base URL and exact upstream model identifier with the provider's instructions. A chat website address or marketing model name may not be an API endpoint or identifier.

If the error points to authentication, access or quota, check that specific account setting with the provider or administrator. Do not paste credentials into the conversation or broaden access just to make a test pass.

The configuration saved, but the session still fails

Saving is not the same as a passing connection test. Confirm the intended model is selected in that session; do not assume changing a default changed an existing session. Then retry the small text task above.

A short task works, but a long input fails

Check the reported limit and the model's actual context capacity. Remove unrelated input or use a smaller excerpt. Increasing the configured context number does not increase the provider's limit.

Chat works, but tools or files fail

Inspect the tool result, readiness reason, execution environment and permissions using the tools guide. A working model connection does not install plugins or make a remote machine's files available. Check upload and processing status for attached files.

A tool action times out or has an unclear result

Do not immediately repeat a write or send. Inspect the target system to establish whether it already happened. If the outcome remains uncertain, stop and ask the owner or administrator; use the human oversight guide before retrying.

Change one relevant setting at a time and retain the new error if it changes. For support, share the version, provider/protocol name when appropriate, failing step and a redacted error—not keys, headers, full configuration or private task content.
