Manage AI agent memory in AgReady

Save useful preferences, inspect what was recorded, and check whether a later answer follows them. This guide separates a stored memory from its use in a response, with a harmless practice exercise and checks for missing or stale information.

These controls describe the October 2026 development interface. Your installed release may differ; this is not a claim that every control is available in v0.0.1.

Know what you are saving

  • Conversation history records the exchange in a session.
  • Active context is the material assembled for a model request. Long conversations can be summarized; a visible history is not a promise that every message is included verbatim.
  • Long-term memory holds information that can be used across sessions, with a type, scope and source evidence.
  • A skill describes a repeatable method. Save a procedure as a skill rather than filling memory with a whole manual.

Memory can come from a manual entry, an explicit request to remember something, or background extraction from conversation history. Do not assume that only statements beginning “remember” can contribute to memory. Extraction is selective, and a saved entry is not guaranteed to be selected for every future turn.

Inspect what is remembered

  1. Open My memories.
  2. Search for the relevant subject. Use the type, scope and source filters to narrow the list.
  3. Open View details on an entry.
  4. Read its content and Original evidence, not just the title. Check when it was recorded, its scope and whether the source still supports it.
  5. If you intend to rely on it for a current decision, confirm that it is still applicable.

A confidence label describes the record, not an independent fact-check. A remembered deadline or decision may have changed since its source conversation.

Add a deliberate memory

Use Add memory to record a stable, non-sensitive fact or preference. Select a type, give it an appropriate scope, and write a short content statement. Use the title and context fields to make its meaning clear.

For example, if it reflects your actual preference: “For my weekly project briefs, put unresolved decisions before background notes.” This is a preference, not authorization to publish or send a brief.

Submit the form, then confirm the entry appears and inspect its details. If you ask the agent to remember something instead, the change can be queued for background processing. A conversational acknowledgment alone does not prove it has been stored; check My memories.

Do not save passwords, API keys, authentication tokens or other secrets. Even where the product checks for credentials, do not rely on detection to make unsafe input safe.

Try a harmless memory check

This optional exercise uses a fictional Cedar project. It is instructional guidance, not a reported AgReady test result or a promise of reliable recall. First verify a small text-only model task. Continue only if you want to create a test memory in your own instance.

1. Save a clearly scoped test preference

Use Add memory with the title Cedar practice brief format and a preference type and scope appropriate for the available controls. Keep the fictional project boundary in the content itself:

For fictional Cedar practice briefs only, use two headings in this order:
Decision needed
Background
This is a test preference, not permission to send or publish a brief.

Submit once, then find the exact entry in My memories. Open its details and verify the full text, scope and available source evidence. Record whether the entry actually exists before testing a reply. If it is missing or still processing, use the checks below instead of adding copies.

2. Check a later reply separately

Where available, open a new agent session that is eligible for the memory's scope. Do not paste the saved headings into that session; otherwise the prompt itself supplies the format. A separate session reduces direct repetition from the original conversation, but does not prove that all other sources of context are absent.

Turn these fictional notes into a short Cedar practice brief.
Use my saved Cedar practice brief format if it is available.
If you cannot find that preference, say so instead of claiming to remember it.
Use only the notes below for project facts. Keep their source labels.
Do not invent an owner, date, decision or completed review.
Do not change memories, files, schedules or external accounts.
Do not send or publish anything.

[M1] Cedar: a reviewer for the draft has not been chosen.
[M2] Cedar: a draft outline is available.

If the saved preference is applied, the reference structure is:

  • Decision needed: choose a reviewer for the draft [M1].
  • Background: a draft outline is available [M2].

Check the headings and their order, both source labels, and the absence of invented facts or external actions. If the preference is unavailable, an honest explanation leaves its use unverified; it does not prove that the stored entry was deleted.

Keep three observations separate: the memory record exists; available context evidence shows it was selected; the answer applies it correctly. A correct answer alone does not prove memory retrieval, and the agent saying “I remembered” is not independent evidence. If the interface does not expose selection evidence, report that part as unverified rather than inferring it from the wording.

3. Check a current-task exception

In the same test session, give this narrower instruction:

For this reply only, use the same [M1] and [M2] notes to return exactly
two bullets with no headings: one unresolved decision and one background fact.
Keep the source labels. Do not change the saved Cedar practice preference.
Do not change files, schedules or accounts, or send or publish anything.

The reply should follow this explicit two-bullet instruction. A saved formatting preference should not override a current task constraint. Inspect the saved entry separately if you need to confirm it was not changed; the response format alone cannot show that. Keep the test entry only if you want it, or review the exact entry's delete action and confirmation to remove it deliberately.

Correct stale information

If an entry is wrong, stop relying on it. The memory page provides add, inspect and delete controls—not a general inline editor. You can remove the incorrect entry through its delete action and add a corrected entry when appropriate. Read the confirmation carefully: deletion is not an undoable editing shortcut.

Check the list after the operation. This removes the selected memory record; it does not demonstrate that source conversations, exported copies, backups or provider-side records have been erased. Clearing a session's history is also not the same operation as deleting long-term memory.

Troubleshoot missing or unused memories

The agent acknowledged a request, but no entry appears

Check the selected account, search terms and type, scope and source filters in My memories. Inspect any visible processing state. A request may still be queued, and selective extraction may not create the entry you expected. Do not repeatedly submit the same preference while its outcome is unclear.

The entry exists, but the answer ignores it

Check its content and scope against the current session and task. Inspect context or source evidence where available. Storage and selection are separate; an entry is not guaranteed to appear in every model request. For work that matters now, restate the needed instruction in the current task, then review the answer. That resolves the task but does not prove memory retrieval.

The answer repeats an old deadline or preference

Identify the outdated statement and provide the current authoritative source in the task. Inspect the relevant memory before removing anything; the old statement may also appear in conversation history or supplied files. Correct the exact record when needed and review the next answer against the current source.

A deleted memory or similar statement seems to return

Compare the record's content, scope and source evidence with what you removed. Check for a separate entry or old source material before assuming deletion failed. Background extraction and conversation history are separate from the selected memory record. Do not clear all history or delete unrelated memories as a diagnostic shortcut.

If you need help, share the product version, affected control, processing or error state, and a non-sensitive reproduction. Redact memory content and source evidence that contain private information; never include credentials.

Keep the current task explicit

For important work, state the current constraint directly: “Use the attached approved plan dated Tuesday; do not use an older launch date.” If a response appears to rely on stale information, identify the conflict and ask it to recheck the source. Memory can reduce repeated explanation, but it cannot replace fresh evidence or grant new permission.

Read sessions and context for conversation history, or skills for repeatable procedures.
