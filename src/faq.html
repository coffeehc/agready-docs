Installation and access

Where can I download AgReady?

Start with the platform download guide. AgReady Server v0.0.1 includes the Web UI and has Linux and macOS archives for both AMD64 and ARM64. Check the latest release, choose the architecture of the machine that will run the Server, and review the release terms and checksums before use.

Does AgReady run on Windows?

The v0.0.1 release does not include a native Windows Server archive. The Web UI is opened in a browser after an instance is running; that is different from installing the Server on the computer running your browser. Do not treat browser access as evidence of native Windows support.

Can I sign up for a hosted account on this website?

This website provides documentation and links to self-hosted resources. It does not provide a public hosted login or self-service signup. To use an existing instance, ask its administrator for the correct address and access. For a new instance, follow Install and start AgReady, then the illustrated setup guide.

Is AgReady free or open source?

Read the LICENSE and EULA attached to the official AgReady release before use. A public download does not itself grant free-use or open-source rights. Model services, hosting and integrations may have their own charges and terms; check them separately.

How is AgReady related to xAgent? Can I migrate?

AgReady grew out of a branch of xAgent and has its own releases and setup instructions. Normal installation and upgrade do not migrate xAgent data. The v0.0.1 release notes describe a separate migration tool for PostgreSQL to PostgreSQL; SQLite migration is not supported by that tool. Review the release notes and backup and recovery guidance before planning a migration.

Models and tools

Does installing AgReady give me a working AI model?

Installing the Server is separate from configuring a model connection. You need the correct endpoint, API protocol and model identifier, plus credentials when required by that endpoint. Test the connection and a small task before using it for routine work. See Configure and test a model connection.

Can I use a model running on my own machine?

Use an endpoint whose API protocol and capabilities are supported by your installed AgReady version, and which the AgReady Server can reach. A local model name alone does not establish compatibility. Test your actual connection; these guides do not certify every provider, model or local model server.

Are tools and plugins included with the Server?

The v0.0.1 Server release includes the Web UI. AgentPlugin and Runtime Assets have separate release directories and versions. Installing the Server does not establish that a tool is installed, reachable or authorized. Use the tools guide to check the execution environment and access a task needs.

Is AgReady just a chat interface?

AgReady is designed for multi-step assignments using session context, tools, skills, memory and working files. The capability guide explains these workflows. Feature availability depends on the installed version, model, tools and deployment. Development-interface screenshots and example prompts are not evidence that a particular release has completed your task.

Privacy and control

Does self-hosting keep all my data on my machine?

Not necessarily. Self-hosting determines where you run the AgReady instance, but model requests and tool calls can involve external services. Review the deployment, model provider, integrations and their settings before supplying sensitive material. A local model does not make a separately connected external tool local.

Does AgReady act without asking?

Do not assume every action has the same approval behavior. State your limits and configure permissions before use. Sending a message, publishing a file or changing a production system needs a clear authorization boundary. Read Review actions and keep control before connecting important accounts.

What does “Agent Ready” mean?

Agent Ready is the author's vision of systems that agents can operate through APIs while people retain observation, intervention and direct control, both in AgReady and in connected systems. It is a direction for the product, not a claim that every application is already connected or every action is automated.

What analytics does this website use?

Optional Google Analytics is off until you allow it. You can decline it without losing access to the website and change your choice through Google Analytics preference in the footer. Cloudflare provides website delivery and performance measurement separately; the Google Analytics choice does not disable Cloudflare measurement.

See the Website Privacy Notice for the details. Website analytics preferences do not configure the data flow of your AgReady instance, model provider or integrations.

Your first task

What should I try first?

Choose a small task whose answer you can verify: summarize two non-sensitive notes, flag contradictions and list unresolved questions. Avoid production accounts for an initial experiment. Use the first-task example or the verifiable task template to define inputs, scope and acceptance checks.

Where should I start when setup or a task fails?

Use the first-use diagnostic checks to separate startup, browser access, model connection and task execution. Keep the exact redacted error and check one layer at a time before reinstalling or repeating a request. Never send API keys or a full unreviewed configuration in a support message.

How do I know a task is finished?

Compare the deliverable with the acceptance checks you set before execution. Check sources, missing items and unintended side effects. A fluent answer or successful tool call is evidence of activity, not by itself evidence of completion.
