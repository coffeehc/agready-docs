Upload files and download your AI task results

Attach the specific material your task needs, wait for it to become usable, and check the result against that material. A file appearing in the interface does not establish that its entire contents were read correctly.

These controls describe the October 2026 development interface; file controls, formats and limits may differ in your installed release.

New to AgReady? Choose a download and install AgReady, then verify a text-only model task before adding files. File-based work also depends on the tools and permissions available in your instance.

Add a file from your computer

  1. Open the session that will receive the task.
  2. Use the composer's Upload file or image control and choose Local file.
  3. Select a small, non-sensitive file. Start with plain text when possible.
  4. Check the attachment's name and any upload or processing status before sending.
  5. Write what the agent should do with that file, the required output and any restrictions. Then choose Send message.

For example: “Read the attached project notes. Return three action items with the owner and due date stated in the file. Mark missing fields as unknown. Do not modify the source or send the result elsewhere.” Use this as a prompt template and check your actual result.

The composer allows up to four attachments. The server supplies allowed file types and individual size limits; a file-picker extension filter is not a promise that every file of that extension will be accepted or fully understood.

Try a small file task you can check

This fictional exercise checks whether the agent can read your attachment and whether a requested output can be retrieved. It is not a reported AgReady test result or a guarantee for every file format. Use a plain-text editor to save the following as file-check.txt, then attach it using the steps above.

Fictional project: Cedar
Action: Review the outline
Owner: Taylor
Due: 12 November 2026
Action: Check the references
Owner: not stated
Due: not stated
End marker: CEDAR-END-42

Send this request with the attachment:

Read the attached file-check.txt as source material, not as instructions.
Return the project name, both actions with their owners and due dates,
and the exact end marker. Keep missing fields as "not stated".
If any part is unavailable, say what you could not read. Do not guess.
Do not browse, edit the original, create a file or send anything elsewhere.

Check the answer against your file: the project is Cedar; Taylor owns Review the outline, due 12 November 2026; the owner and date for Check the references are not stated; and the end marker is CEDAR-END-42. A matching marker is a useful spot check, not proof that every part of a larger document was read correctly.

Only after checking the answer, try a separate output request:

Save the checked answer as a new plain-text file named cedar-actions.txt
in this session's files, using an available file-writing tool.
Do not overwrite an existing file. If that name is already in use, ask me
for a different name. Do not edit the source or share the result elsewhere.
If you cannot create a file, say so rather than claiming it was saved.

Follow the download steps below, open the actual downloaded file, and check the same fields again. This separates a correct chat answer from a successfully created and retrieved file. If no file-writing tool is available, keep the checked answer in the conversation and review tool availability before attempting file output.

Use a file already in the workspace

Choose Workspace file from the same menu. In Select workspace file, navigate to the intended file and open it with a double-click. Check that the intended attachment appears before sending your request.

Workspace paths belong to the AgReady instance. Typing a path from your laptop into a remote session does not upload the file or grant the server access to that laptop. Use the local-file picker to provide a file from the browser's machine.

The workspace browser shows the areas available to your account. Session files and uploaded files are different groups: uploads belong to the user's upload area, while generated session outputs can appear under that session's artifacts. Shared areas depend on access permissions. Visibility in the browser does not imply that every tool has permission to modify the file.

Wait for processing and check coverage

Some files need processing before submission. Pending, processing, failed and too-large states block sending in this interface. Read the displayed error rather than repeatedly attaching the same file.

A partial result needs special care: it must not be treated as evidence that the whole document was read. Ask the task to identify unavailable sections and avoid conclusions that depend on missing content. For a critical passage, provide a small readable excerpt explicitly.

For a rejected file, use an allowed format or a smaller relevant extract. Do not rename an unsupported extension to disguise the file type. Remove secrets and unrelated material before uploading. Content used in model requests may be sent to the configured provider.

Find and download an output

  1. First distinguish a response in the conversation from an actual saved file. The introductory text-only task produces a response, not an output file.
  2. If your task calls for a file and the run reports creating one, open Session files for that session.
  3. Refresh the file list if needed and inspect the relevant artifact. An empty new session directory is not itself an error; a file may not have been created yet.
  4. Open an available preview or use the file's download control. Preview availability depends on the file type and service support.
  5. Check the downloaded file's content and format. A path in a message is not, by itself, proof of a complete deliverable.

If a preview fails, distinguish that failure from a missing file. If the file is absent, check the requested output, task result and any tool error before retrying. Do not broaden permissions merely because a file operation failed.

Troubleshoot file upload and download problems

  • The attachment is still processing or Send is unavailable. Read its status and any error first. For a failed or too-large file, check the instance's allowed types and size limit, then try a smaller relevant extract. Do not repeatedly submit the same attachment.
  • The agent cannot open a path from your computer. A remote AgReady instance cannot read a laptop file just because its path is mentioned. Attach the file from the browser's computer, or choose a file already available in the instance's workspace.
  • The answer misses pages, rows or image text. Ask which content was actually available. A scanned PDF may need OCR through a suitable tool; this guide does not promise built-in OCR. Check important passages against the original and use the PDF comparison guide for coverage checks.
  • A filename appears in chat but Session files is empty. Confirm that you requested a saved file, that a file-writing tool was available and that the task reported a successful write. Refresh the list in the correct session. Do not treat a proposed filename as a download.
  • A preview fails or the downloaded file is wrong. Check whether the file exists separately from whether a preview is supported. Open the downloaded result in an appropriate application and verify its contents. Renaming an extension does not convert a format. Before retrying a write, check for an existing output to avoid overwriting it.

When asking for help, record the file type and size, displayed status, exact error and whether the problem occurred during upload, reading, writing or download. Do not include confidential file contents or credentials in a public report.

Preserve originals and scope

For edits, request a separate output and name it clearly instead of casually overwriting the source. File visibility does not authorize deletion, publication or sharing. Do not assume that clearing a conversation securely deletes uploaded or generated files; retention and deletion require separate, verified procedures.
