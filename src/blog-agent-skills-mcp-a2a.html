Agent Skills vs MCP vs A2A: what each adds to an AI workflow

Agent Skills describe a reusable method. MCP connects an AI application to tools and context. A2A lets independent agent applications communicate. A useful workflow may combine all three, but each solves a different problem.

On October 22, 2026, Anthropic announced the donation of Agent Skills to the Agentic AI Foundation. That makes this a useful moment to sort out the terms before choosing an integration or importing a package.

Three layers of an agent workflow

Agent Skills: how to approach the work

The Agent Skills format packages instructions with optional supporting resources. Its specification uses a SKILL.md file with metadata and a Markdown body. Scripts, references and templates can accompany it. A research skill might explain how to compare sources and mark uncertainty.

MCP: which operations and context are available

The Model Context Protocol architecture defines a client-server interface. Servers can expose tools, resources and prompts. A document service might expose a search tool and readable source material. The host still decides how to use that information in its agent workflow.

A2A: how to work with another agent application

The Agent2Agent protocol lets independent agents discover capabilities, exchange messages and coordinate tasks. It does not define how an application orchestrates its own subagents. An internal team feature and an A2A connection are separate things.

There is also a naming trap: an A2A Agent Card can describe an agent's “skills.” Those capability descriptions are not automatically downloadable Agent Skills packages.

Example: a source-linked research brief

Consider a fictional team comparing three public documentation products. It wants a brief with source links, clear unknowns and a list of questions for further review. This is a workflow design, not a measured product run.

  1. Start with the method. A reusable skill defines the comparison fields, source requirements and how to handle conflicting information. The current task supplies the three product names and research cutoff.
  2. Add access only where needed. If the sources are already supplied as text, the first draft may need no external tool. If the task requires live documents, a connected read tool can retrieve them. An MCP server is one possible way to provide that access.
  3. Delegate a bounded question when helpful. If a separate specialist agent offers an appropriate service through A2A, send it an authorized question and the minimum necessary material. Ask it to return evidence and unresolved questions with its answer.
  4. Reconcile the result. The main task checks the returned evidence, resolves duplicates and produces one brief. A remote task marked complete does not establish that every claim in its answer is correct.

The skill can explain how to use a tool, but it cannot create a working connection merely by naming one. The connection supplies access, while the task and account permissions determine what may be done with it.

Choose the smallest useful addition

  • “I keep rewriting the same review instructions.” Start with a skill and a small example that makes the desired result clear.
  • “The agent needs current data from this system.” Inspect the available tool connection, its supported operations and account scope. Check whether the service offers MCP or another supported interface.
  • “Another agent service already performs this specialist task.” Inspect its A2A interface, authentication, data-sharing terms and result format.
  • “I want several roles inside one workspace.” Start with the workspace's own team or subagent controls. A2A may be unnecessary.

A simple text-only job can be the best starting point. Adding a protocol creates new things to configure, authorize and troubleshoot; it should remove a concrete obstacle.

Where these fit in AgReady

AgReady's current development implementation includes Skills, MCP tool runtimes and an A2A Client. They have distinct roles:

  • Skills can be imported from ZIP packages or accepted SKILL.md links, and selected for a session. See creating and testing a reusable skill.
  • MCP tool connections supply tool runtimes. Inspect the actual operations and readiness rather than assuming every server feature or protocol version is supported. See tools and runtime assets.
  • The A2A Client discovers a remote Agent Card, sends tasks, follows their status and receives messages and artifacts. The current implementation supports A2A v1 JSON-RPC and HTTP+JSON interfaces. It does not provide an A2A Server that publishes local agents for outside callers.
  • Agent teams organize work within AgReady. They are separate from remote A2A agents. See the agent-team guide.

These capability statements were checked against development source on November 11, 2026. Installed releases, account permissions and configured services determine availability. This is not a claim of universal package compatibility, protocol certification or tested performance.

Before connecting a new capability

Write down its purpose, owner, inputs, output and external destinations. Inspect instructions and scripts before loading a skill. Check both the tool's functions and the connected account's permissions. For a remote agent, define what it may receive and what evidence it must return.

Begin with non-sensitive input and a read-only or draft-only task. If an operation times out after submission, inspect the existing task or destination before retrying. A fresh request can duplicate work even when the first response was lost.
