Resume AI agent tasks with clear context

Keep related revisions in one AgReady session. When returning to a long or interrupted task, restate the current goal, verified progress, source material and allowed next step before continuing. A visible conversation history does not mean every earlier message is included verbatim in each model request.

These controls describe the October 2026 development interface; labels and availability may differ in your installed release.

Continue this session or start another?

  • Continue the existing session for a correction or next step in the same assignment. Say which requirement changes and which ones remain.
  • Use a separate session for an unrelated assignment or a deliberate fresh start, where available. Provide the required sources again and state its permissions explicitly.
  • Check the run state first if work was interrupted. A new conversation does not establish whether an earlier send, write or other external action finished.

A new session is an organizational choice, not proof of an empty workspace, cleared memory or revoked account access. Check those resources separately when they matter.

Start a bounded assignment

  1. Open Main Agent for the introductory text-only exercise, or open the existing session for the assignment you are continuing.
  2. Check the selected model.
  3. In Message AgReady, supply the relevant input, requested output and limits. For example: “Compare these two supplied notes. Return differences in the conversation. Do not browse, change files or send messages.”
  4. Use Send message once. Watch the displayed state and any error or approval request.
  5. Review the response against your input before adding the next instruction.

When a separate agent session is appropriate and available, use New agent session, select an available agent, enter a session name and choose Create session. Enter the concrete assignment after opening it. If no suitable agent is available, do not assume one has been installed or configured.

Continue without losing the objective

For a correction to the same deliverable, stay in the session and specify exactly what should change. Quote a short source passage or identify the attached file when the correction depends on it. For a substantially different assignment, use a separate session where available and provide its required inputs explicitly.

Do not assume a new session inherits all earlier material, permissions or files. A useful opening brief includes:

  • the outcome and output format;
  • which supplied material is authoritative;
  • actions allowed now and actions requiring approval;
  • unresolved questions and a concrete acceptance check.

Use a short resume brief

After a pause, context compression or a move to another session, fill in this brief from the sources and results you can actually inspect. You can ask the agent to draft it, but review it before treating it as the current state. Do not include passwords, API keys or unnecessary private data.

Resume this assignment by checking the state first.
Goal and output: [the current deliverable, audience and format]
Sources: [the relevant notes, file versions or source links]
Verified completed work: [what I checked, with a result or source reference]
Pending work: [what still needs doing]
Uncertain outcomes: [what may have happened but is not confirmed]
Current decisions: [the latest requirements and what they replace]
Allowed now: [specific resources and actions]
Do not repeat: [completed actions or steps whose outcome is uncertain]
Next proposed step: [one bounded step]
Acceptance check: [how I will judge the result]

Return a short recap and flag missing or conflicting information.
Do not begin the remaining work or repeat an external action yet.

Check the recap, then authorize the specific next step. If the agent cannot access a cited source, supply the relevant excerpt or attachment rather than asking it to reconstruct missing details. A filename or link in the brief is not proof that its contents were read.

Try a text-only correction

This fictional practice exercise uses only the conversation. It is a prompt and reference answer, not a reported AgReady test result or a test that forces context compression.

First send:

Use only these fictional Harbor project notes.
[N1] The draft review target is May 14.
[N2] A reviewer has not been assigned.

Return two bullets: review target and reviewer status.
Cite the note labels. Do not infer completion or invent missing facts.
Reply only here. Do not browse, change files or memories, schedule work,
send messages or publish anything.

After the response finishes, send this correction in the same session:

Update the same Harbor brief using this new note:
[N3] The review target is now May 16, replacing the May 14 target in N1.

Keep the two-bullet format and the earlier action limits.
Use the current target, retain any unchanged reviewer status and cite sources.
A target date is not evidence that the review happened.

Reference answer for the corrected brief:

  • Review target: May 16, replacing May 14 [N3].
  • Reviewer status: not assigned [N2].

Check: the revised target replaces the earlier one; the reviewer remains unassigned; no completed review, new owner or year is invented. The task stays in the conversation. If the answer is wrong, quote the affected note and request only that correction. A correct answer demonstrates this small revision, not reliable recall of every detail in a long session.

Understand history, context and memory

The conversation you can browse and the material assembled for the next model request are related but not identical. Long conversations can be compressed into summaries while recent material is retained. Compression is not a guarantee that every detail survives unchanged.

Where context usage is shown, distinguish estimated input from provider-observed usage and reserved output. Treat it as a diagnostic aid, not proof of unlimited capacity. If the interface says context compression is in progress, wait until it finishes rather than repeating the operation.

Cross-session memory is separate from the context assembled for this assignment. A preference saved for later work is not a substitute for supplying the current document or checking the latest task state. Neither a generated recap nor a memory entry independently proves that an external action completed.

For consequential facts, repeat the short authoritative statement or refer back to its source. If an answer contradicts an earlier instruction, point out that discrepancy rather than relying on the agent to infer the correction.

Stop, archive, restore or clear

Stop current run

Interrupt work that is currently running

It does not undo an external action or prove every queued message has been removed. Inspect the resulting state.

Archive

Put an available session aside as read-only

Archiving stops active execution; it is not deletion or a backup. Some managed sessions have separate lifecycle restrictions.

Restore

Make an archived session available again

Restoration does not automatically resume the runner or consume its queued work. Inspect the restored state before asking it to continue.

/clear-history

Deliberately reset the current session's conversation context

This resets the visible history boundary and related context state. It is not a secure-erasure command or a way to undo completed actions.

Do not clear history as routine troubleshooting. Preserve any information you still need first, and use the command only when you intend a reset. Main Agent is not a disposable session; deletion controls are limited to eligible sub-sessions. Review the displayed confirmation before deleting anything.

Troubleshoot before retrying

The answer uses an old requirement

Quote the latest authoritative instruction and identify the earlier requirement it replaces. Ask for the affected section to be corrected, keeping other requirements unchanged. An incorrect answer alone does not establish that compression caused the problem.

The agent cannot use an earlier file

Confirm the attachment or workspace file is available in this session and identify the intended version. Reattach or supply the needed excerpt if appropriate. Follow the file-processing checks; do not assume visible chat history contains the complete document.

Context compression is still in progress

Wait for the displayed state to change rather than submitting repeated copies. If an error appears, preserve its wording and the current task state before troubleshooting. Do not use /clear-history as the first response.

A stopped run may already have changed something

Inspect the destination and the available tool result before retrying. Keep the step marked uncertain until its outcome is known. Use the human oversight guide when taking over or granting a new action.

No response appears

Confirm the selected session and model, then check whether the message was submitted. An active run, pending approval, processing attachment or connection error needs a different response. Do not repeatedly resend while the previous outcome is unknown. Use the diagnostic checks, then retry a small text-only request once the state is clear.
