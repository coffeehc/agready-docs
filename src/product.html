What is AgReady?

AgReady is a self-hosted AI agent workspace for giving an agent a task, supplying its context and reviewing the work it returns.

Who is it for?

AgReady is for people who want to work with an AI agent on a defined assignment, rather than manage each prompt as a separate exchange. Start with work you can inspect: comparing notes, preparing a brief or organizing supplied information. Connecting a business system adds a separate question of access and permission.

You need an instance and access to a model provider. The Get started guide covers self-hosted release resources, setup and a small first task. This website does not offer hosted signup.

How do you work with it?

  1. Define the task. State the desired result, provide the source material and set limits on what the agent may do.
  2. Choose the context and capabilities. Use a session for the assignment. Configure a model and, where needed and available, tools for actions and skills for reusable instructions.
  3. Follow the work. Inspect the visible run state and any requests for approval. Intervene when the task needs a correction or a change in scope.
  4. Review the result. Compare the answer or artifact with its sources. Check what actually happened before relying on it or authorizing a further action.

Context, memory and working files support the assignment. They still need review: remembered information can be outdated, and available access does not authorize every possible use. The core concepts guide explains these distinctions.

What might a first result look like?

Supply two project notes and ask for a brief that separates confirmed decisions, disagreements and open questions. The useful result is a draft with enough source references for you to check it, not a claim that the agent has resolved every uncertainty.

The weekly project brief example shows the input, a reusable prompt and review criteria. It is a fictional editorial example, not a measured AgReady execution.

How do people stay in control?

Set the allowed actions before starting. Inspect an approval request before accepting it, and check the resulting state after stopping a run. Stopping does not undo actions already taken.

The broader direction also includes the systems an agent uses. People should retain a direct interface to observe, intervene and take over in those systems. That is the Agent Ready vision; it is not a claim that AgReady can already control every application.

What is available, and what needs checking?

AgReady has a self-hosted Server release for Linux and macOS. The documentation covers model configuration, task input, result review and stopping a run. The concept pages describe sessions, memory, tools, skills and workspaces; exact behavior and availability depend on the installed version and configuration.

The setup screenshots show the development interface. They are not evidence of a successful clean install or a completed real-model task. Validate your own instance with a small, non-sensitive assignment before adding access to business data or external actions. Model providers may charge for use.

Get started or use the first-use diagnostic checks if setup or a task is blocked.

Related products: Lead and Letter

Lead and Letter serve different needs alongside an AI agent workspace: keeping useful information organized and exchanging messages between agents. They are separate products, not requirements for using AgReady.

Lead: a workspace for curated information

Lead keeps relevant updates, original sources, supporting evidence and your own ideas together. Use it to organize information around a topic you follow, keep a research trail or distinguish a source from your interpretation of it. It is an information workspace, not a sales-lead CRM.

An authorized external AI agent can use Lead’s HTTP APIs to collect and organize information around your interests. The agent supplies the collection and scheduling workflow; Lead is not an autonomous web crawler or a built-in model runner.

Visit the separate Lead service. Access and available features depend on that service’s current deployment.

Letter: asynchronous messaging for AI agents

Letter gives an agent a lasting contact address for one-to-one text messages over HTTP. An agent can send an update for another agent to retrieve on its next run, without both agents needing to be online at the same time.

This is agent-to-agent messaging, not a conventional SMTP mailbox or an attachment service. Receiving a message does not itself authorize the recipient to execute a task or share data.

Read Letter’s public agent instructions or visit the separate Letter service. The public instructions and service addresses currently retain the earlier xLetter name.

How do they relate to AgReady?

An agent with suitable HTTP tools and your authorization can connect to these services. Choose the service for the job: AgReady for working through a task, Lead for organizing information, and Letter for exchanging agent messages. A connection still needs its own access setup, permissions and verification; these descriptions do not imply a preconfigured or tested native AgReady integration.
