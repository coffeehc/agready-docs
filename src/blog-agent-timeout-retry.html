PRACTICAL GUIDE · NOVEMBER 14, 2026

AI agent timeout? Check what happened before you retry

Your agent stopped responding, but did the work stop too? Before asking it to start again, check the result where the action was supposed to happen.

This guide is for interrupted tasks and agents repeating work. It offers a recovery checklist and a fictional example, not an AgReady reliability benchmark or a guarantee against duplicate actions.

Start with the destination, not another “try again”

A missing final reply does not tell you whether the task succeeded, failed, or is still running. Ask for a read-only check of the intended destination: the saved document, the published page or the external service's action record. Use the task's time window and any recorded operation identifier to narrow the check. Do not expose credentials in the recovery report.

For actions with external effects, a timeout can leave the outcome uncertain. OpenAI's Agents SDK recovery guidance explains that an external action can finish before its completion is saved locally. An approval does not guarantee exactly-once execution. It also warns that a simple lookup finding nothing may be insufficient: records can lag or an earlier request can still be running. Treat an unresolved outcome as unknown rather than automatically repeating the action.

Separate four outcomes

  • Confirmed not started: establish that the earlier attempt did not act and is no longer able to act. Retry only the still-authorized unfinished step.
  • Still running: inspect its status instead of launching a competing copy. If you stop it, verify what stopping actually canceled.
  • Completed: inspect the saved result and return its link or missing summary. Do not recreate it just because the final chat reply is absent.
  • Unknown: preserve the available evidence and leave the consequential action pending. State what would resolve the uncertainty.

A status label in one interface is not always a complete record of another system. Where records conflict, explain the conflict instead of selecting the most convenient answer.

A fictional interrupted weekly brief

Imagine you asked an agent to read five project notes, save a weekly brief and return a link. Its conversation ends after “saving the brief.” This is an illustrative scenario, not a reported AgReady run.

  1. Check the intended folder and the recorded save result without changing anything.
  2. If the expected document exists, open it. Confirm that it covers the five notes and identifies unresolved decisions.
  3. If it is complete, return that document's link. The remaining task was delivery of the result, not another document.
  4. If it is incomplete, identify the missing section. Update only that section if the existing permission covers the edit.
  5. If you cannot establish whether the save finished, report the uncertainty before creating another copy.

Sending the brief to other people is a separate action. Permission to prepare or repair it does not authorize distribution. A recovery attempt should not expand the original task.

A recovery prompt you can reuse

Check the interrupted task before retrying it.
First inspect available records and the intended destination without changing anything.
Separate completed work, work still running, confirmed unfinished work and unknown outcomes.
For each conclusion, provide the evidence or say what you could not verify.
Do not recreate an existing result, send again, republish or repeat an uncertain external action.
Do not interpret a missing search result as proof that the action never happened.
Return existing results that are complete. List the smallest remaining step.
Continue only if that step is within my original authorization and its prior outcome is resolved.
Otherwise explain exactly what needs checking or approval.

Replace “the interrupted task” with its specific goal and destination when opening a new session. Include useful links and identifiers, not a copied secret or an entire private conversation.

If the task is scheduled, check the next run too

Stopping one run and disabling future activations are different decisions. A manual retry while a timer remains active can create overlapping work. Check the schedule and next run before resuming; change them only within the user's permission.

In AgReady, the recurring task guide explains how to inspect trigger records and session output. A successful activation means a session was started, not that the requested deliverable was completed. Use the operations guide for the documented controls in your installed version.

Use both places where you have control

The Agent Ready vision combines agent work through APIs with human control in AgReady and in the connected system's own UI. For recovery, compare the session's account of its work with the actual destination. Which records and controls are available depends on your installed release, tools and permissions.

This checklist does not establish that your AgReady deployment or any connected tool provides automatic deduplication, rollback or exactly-once execution. When an important action cannot be verified, keep it unresolved rather than making a confident guess.
