What can you do with AgReady?

AgReady is a self-hosted AI agent workspace for working through an assignment from its initial brief to a result you can review. You provide the goal and relevant material, choose a compatible model, and make the necessary tools available. The agent can plan steps, use those tools and carry the work forward in a session.

Use this guide to understand where AgReady fits into your work and which guide to read next.

Start with a real piece of work

A useful starting point is something you already need to finish: a research brief, a comparison of documents, an updated report or a recurring review. Choose a deliverable whose usefulness you can judge.

You do not need to design a demonstration. Bring the actual question, the material you are allowed to use, and a clear description of what would make the result useful.

For example:

  • Compare several supplied documents and explain where they agree, conflict or leave questions unanswered.
  • Review public source pages and prepare a research brief with links supporting its conclusions.
  • Turn working notes into a report that separates facts, decisions, risks and next steps.
  • Review a draft against an agreed structure, then produce a separate revised version.
  • Repeat an established information-review workflow, keeping the result ready for a person to inspect.

These are task patterns, not a claim that every model or default installation can complete them. File operations, web access and other actions need suitable tools. The model’s capabilities also affect the result.

For a first installation, follow Get started. If your instance is already working, choose a real assignment and define its output.

Research and compare information

AgReady can help organize source material into an answer to a specific question. You can supply text or files, or use an available tool to retrieve authorized sources.

A good research brief states:

  • The question you need answered.
  • Which sources to use, and which sources are outside scope.
  • How current the information needs to be.
  • The format of the result.
  • What to do when evidence is missing or contradictory.

Ask the agent to connect important conclusions to their sources. A useful comparison should preserve differences between the sources rather than turn uncertainty into a confident answer.

For public-web work, distinguish reading a known URL from searching for new sources or interacting with a website. Those operations require different capabilities; a page-reading tool does not establish that interactive browsing is available.

Start with Tools and integrations for tool readiness, and Files and workspace when the research begins with supplied documents.

Prepare and improve documents

Use AgReady to organize material, draft a document, revise its structure or check it against requirements. The brief can specify an audience, a length, required sections and the evidence that must be preserved.

A response in the conversation may be enough for an outline or short draft. If you need a saved document, spreadsheet, presentation or PDF, state that explicitly and check that the necessary tools are available.

Keep the source and output distinct. For example, ask for a separate revised file rather than leaving it unclear whether the original should be overwritten.

Review the resulting work for more than fluent writing:

  • Does it preserve the meaning of the source?
  • Are names, figures and dates correct?
  • Are unsupported statements marked as uncertain?
  • Does the delivered file open and contain the intended content?
  • Is it useful for the person who will receive it?

Files and workspace explains how to provide material, check processing and retrieve a saved result.

Carry an assignment across multiple steps

Some work takes more than one exchange. AgReady supports plans, task steps and revisions, while a session keeps the conversation associated with an assignment.

For a longer task, define meaningful stages. A research assignment might first identify the source material, then compare the evidence, and finally produce a brief. Ask for a useful checkpoint where a decision from you could change the next stage.

Keep corrections explicit. If the scope changes, say what changed and which earlier instruction it replaces. When a stage is complete, check its result before relying on it in the next one.

Long conversations can be summarized to manage context. Keep important current constraints and authoritative sources easy to identify instead of assuming every old detail will remain available unchanged.

Read Sessions and context for continuing work, managing history and handling interruptions.

Reuse context and working methods

Memory and Skills address different kinds of repetition.

Memory: useful information across sessions

Memory can retain information worth carrying forward, such as a stable preference or relevant background. You can inspect its contents and source evidence, and remove information that is no longer appropriate.

Use the current task brief for instructions that apply now. A remembered preference should not override an updated requirement.

See Memory and context for managing saved information.

Skills: a method you want to repeat

A Skill packages instructions and supporting material for a recurring kind of work. It can describe how to structure a report, evaluate sources or check a deliverable.

Build a Skill around a method that has proved useful. When a real task reveals a repeatable problem, improve the instructions and check whether the next result addresses it.

Skills do not supply missing connections or authorize external actions. Their required tools still need to be available.

Read Skills and reusable work to inspect, import, request and load a Skill.

Divide larger work among agents

Agent teams provide a way to organize subtasks and bring reports together. They can be useful when an assignment contains distinct pieces of work with clear inputs and outputs.

Before dividing the work, define each part and how its result will contribute to the final deliverable. Check for dependencies: a review cannot evaluate a draft that has not yet been produced.

More agents do not automatically mean a faster or better result. Coordinating their work and reviewing the combined output remain part of the assignment. Team availability and controls depend on the installed version and configuration.

The core concepts guide explains the sessions, tools, Skills and context involved in agent work.

See Work with an AI agent team for creating a team, briefing its manager and reviewing its work.

Run work that needs to recur

AgReady supports persistent timers and configured external event triggers. These provide building blocks for repeated work, such as preparing a briefing from approved sources for later review.

First establish that the underlying task produces a useful result. Then define the trigger, permitted actions, expected output and conditions for pausing the work.

Recurring tasks depend on the server, model and tools remaining available. They can also encounter approval requests or other conditions that prevent completion. Check actual run results rather than treating a configured schedule as proof that work happened.

For the instance’s availability and maintenance, see Upgrades and recovery. Review Human oversight before recurring work can affect external systems.

See Schedule recurring AI tasks for timer settings, activation history and controls for future runs.

Choose the environment and keep control

AgReady runs as a self-hosted service. You choose where to operate it and connect compatible model providers, including locally served models where the protocol and required capabilities are supported.

Self-hosting gives you responsibility for access, maintenance and availability. It does not automatically keep every task local: model requests and connected tools may use external services.

Use Install and start to prepare an instance and Model configuration to verify a model connection.

Before work begins, separate reading from changing, preparing from sending, and drafting from publishing. Use appropriate account permissions and review the available approval controls. If you stop a run, inspect what already happened before retrying or taking over.

The broader Agent Ready vision is that agents operate business systems through APIs while people retain visibility and the ability to intervene, both in AgReady and in those systems. Each integration still needs its own access, permissions and verification.
